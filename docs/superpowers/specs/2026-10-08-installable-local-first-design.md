# Installable Local-First poker.pot — Design Spec

**Status:** Approved
**Date:** 2026-10-08

## Objective / why

Turn poker.pot from a LAN client-server app into a local-first, installable
app. The ledger engine (`src/domain`) already runs anywhere; this work moves
storage into the client, retires the Bun API server, and ships the same app as
an installable PWA (iOS via Add to Home Screen) and an Android APK (Tauri v2),
distributed like clytrade: PWA on GitHub Pages, APK on GitHub Releases, with a
tag-driven Actions pipeline.

Why: the phone currently only works when the home server is reachable, and
nothing is installable. With data on the device, the app works offline anywhere
the phone goes, and one phone passed around the table is fully self-contained.
No account, no server, no subscription.

## Success criteria / definition of done

1. `bun run build` emits a PWA with manifest, service worker, and PNG icon set.
   Installed from an HTTPS URL on iOS Safari (Share → Add to Home Screen), it
   launches standalone and works fully offline.
2. Pushing tag `v0.1.0` makes CI produce a draft GitHub Release containing
   `poker.pot-0.1.0-android-universal.apk`, signed with the release keystore.
   The APK installs on a physical Android phone, works offline, and keeps data
   across relaunch and app updates.
3. No `/api` calls remain in the client; all ledger logic runs client-side via
   `src/domain`; `src/server` (API, storage, location file) is deleted.
4. First run shows the onboarding wizard (import backup or start fresh → add
   players → set limits); the data-directory setup screen is gone.
5. Backup: export all data as one YAML bundle; import supports replace and
   merge; merge asks per conflicting session with an apply-to-all option;
   merge unions the roster by player id and keeps local limits; imports are
   zod-validated and a rejected file changes nothing.
6. Settings shows the app version, last-backup time, and a gentle nudge when
   data changed since the last export.
7. The installed PWA shows a non-blocking "new version available" banner when
   an update is ready; reload is user-triggered.
8. `bun run test`, `bun run typecheck`, `bun run lint` pass, including existing
   domain/UI/theme suites and new Dexie, import/export, and conflict suites
   (fake-indexeddb).
9. README screenshots are regenerated by seeding IndexedDB against the static
   preview build on the transient screenshot port.
10. `bun start` serves `dist/` on `0.0.0.0:7403` as a static preview (no API),
    the dashboard entry keeps working, `bun run dev` serves Vite on `0.0.0.0:7404`
    without an API proxy, and screenshots stay transient on `7407`.
11. Docs match reality: README (install, backup, commands), AGENTS.md (ports,
    commands, release notes), new CHANGELOG.md with the 0.1.0 entry.

## Scope

### In scope

- Dexie-backed client storage replacing `src/client/api.ts`.
- Onboarding wizard and removal of the data-dir setup flow.
- YAML backup export, replace import, merge import with conflict resolution.
- zod validation of imported files.
- Last-backup indicator and data-changed nudge.
- PWA: vite-plugin-pwa, manifest, PNG icons, update banner, HashRouter.
- Icon redesign (pot/chips motif) and generation of all platform icon sets.
- Tauri v2 Android shell (`src-tauri/`), universal APK, release signing.
- Static server replacing the API server for the 7403 live port.
- GitHub Actions: checks, Pages deploy, tag-driven release with draft.
- Keystore generation (Docker) and repository secrets wiring.
- Test port, screenshot rework, docs (README, AGENTS.md, CHANGELOG).

### Non-goals (explicitly out)

- Windows/desktop builds (Android only; iOS via PWA).
- Native iOS builds (no Mac/Xcode available).
- Data sync between devices; optional server mode; multi-device viewing.
- In-app APK auto-updater (updates are reinstalling a newer APK).
- Per-session export (single all-in-one bundle only).
- Changes to betting rules, domain semantics, themes, or house-style system.
- Android PWA install path as a supported workflow.

## Architecture

**Client (the whole app).** React + Vite with hash routing. The client imports
`src/domain` directly; every command runs through `applyCommand` with injected
deps (`newId()` from `src/client/id.ts`, ISO now, `Math.random`). The domain
stays the single source of ledger truth and is already browser-safe.

**Storage layer.** `src/client/api.ts` is replaced by a Dexie-backed module
exposing the same operations (config get/save, sessions list/get/create/
rename/delete, command). Dexie schema v1 holds a single config row, one row per
session keyed by id, and a meta table for `schemaVersion`, `onboarded`,
`lastBackupAt`, and a data-revision counter incremented on every mutation.
`SessionSummary` and balances move client-side using `sessionBalances`.
Read-modify-write command application moves inside a Dexie transaction.

**Backup.** One module builds/exports/imports a YAML bundle:
`{ app: "poker.pot", schemaVersion, exportedAt, data: { config, sessions } }`.
Export renders YAML, then shares via `navigator.share` on iOS or downloads a
blob elsewhere. Import parses YAML, validates with zod, then either replaces
everything after confirmation or merges: new sessions are added, conflicts go
to the conflict sheet (per-row Keep local / Use imported, apply-to-all), and
the roster is unioned by id while local limits stay.

**Screens and flows.** Onboarding wizard on first run (tracked in meta):
import-or-fresh → players → limits → Sessions. Settings gains a Data section
(export, import, last-backup indicator, nudge) and shows the app version.
A slim update banner appears on Sessions/Settings when the service worker has
a waiting version; it never reloads on its own.

**PWA.** vite-plugin-pwa with `registerType: "prompt"`; manifest with PNG
192/512 + maskable icons, apple-touch icon, `display: standalone`, portrait
orientation; service worker disabled when `TAURI_ENV_PLATFORM` is set (the
native bundle carries its own assets). HashRouter everywhere, so Pages,
preview, and the APK behave identically. `navigator.storage.persist()` is
requested best-effort at startup.

**Static server.** `bun start` serves `dist/` (with index fallback) on
`0.0.0.0:7403`; no API routes. `PORT` remains the override. `scripts/live.sh`
keeps its pid/log file behavior; the dashboard entry is unchanged.

**Android (Tauri v2).** `src-tauri/` with `productName` `poker.pot`,
identifier `com.pokerpot.app`, `frontendDist` `../dist`, `beforeBuildCommand`
`bun run build`, default capability (`core:default` only unless the download
fallback plugin is needed), debug application-id suffix `.debug`, and icons
generated from the new source SVG. Release builds sign with the keystore
injected from GitHub Secrets into `keystore.properties`; the collector script
copies the universal APK to `release/poker.pot-<version>-android-universal.apk`.

**CI/CD.** `.github/workflows/`:
- `ci.yml` (called by others): Bun setup, `bun install --frozen-lockfile`,
  lint, typecheck, test, build.
- `pages.yml`: checks, build with `VITE_BASE=/poker.pot/`, deploy to Pages on
  `v*` tags and manual dispatch.
- `release.yml`: on `v*` tags (and manual): checks → Android job (Bun, JDK 17,
  NDK, Rust Android targets, keystore from secrets, `bun run android:apk`,
  collect artifacts) → draft GitHub Release with the APK; `v0.*` marked
  pre-release.
- `version:set` script (future bumps) syncs package.json and Cargo.toml/lock;
  CHANGELOG.md follows Keep a Changelog, starting at 0.1.0.

**Screenshots.** The script builds the app, serves `dist/` statically on the
transient 7407 port, seeds a demo session directly into IndexedDB via
Playwright, and regenerates `docs/screenshots/` (screens plus the
Light/Dark/OLED strip).

## Risks + rollback

- **Android WebView blob download.** Saving the YAML export inside the Tauri
  APK may not work with pure web APIs. Verify on a physical device early; if
  broken, add `tauri-plugin-dialog` + `tauri-plugin-fs` and a capability, with
  the web path kept for the PWA. Import (file input) is unaffected.
- **iOS storage eviction.** WebKit can evict script-writable storage in some
  conditions. Mitigate with `navigator.storage.persist()`, the backup nudge,
  and README guidance; data loss risk remains, which is why export exists.
- **Android signing.** A release APK accidentally signed by a debug key would
  break in-place updates. CI must fail when the keystore secrets are missing on
  a tag build.
- **`gen/android` bootstrap.** Generating the Android project needs the SDK;
  it will be produced once (locally or in CI) and committed, or initialized in
  the workflow if absent. Committing it matches clytrade and keeps builds
  reproducible.
- **CI drift with Bun + Tauri.** Pin Bun, Rust, and Node-compatible tool
  versions; the release job is exercised manually (`workflow_dispatch`) before
  the first tag.
- **Rollback.** Server deletion is recoverable from git history; Pages can be
  disabled; a bad APK can be uninstalled. Roll back a release by re-tagging a
  previous commit after exporting data on test devices.

## Dependencies / ordering

1. Docker is available for keystore generation; JDK/Android SDK are not needed
   locally (CI builds the APK).
2. Pages must be enabled once (Settings → Pages → Source: GitHub Actions).
3. GitHub secrets must exist before the first tag push.
4. Implementation order: storage port → onboarding + backup → PWA/icons →
   static server → tests/screenshots → Tauri Android → CI/release → docs.
5. The first release tag (`v0.1.0`) is pushed only after a manual
   `workflow_dispatch` run succeeds and the keystore is wired.
