**Spec:** `docs/superpowers/specs/2026-10-08-house-style-ui-design.md` (commit

**Date:** 2026-10-08
**Status:** Awaiting approval (gate 2)

## Global constraints (from the spec)

- No changes to `src/domain/`, `src/server/`, `src/shared/`, the REST API, or
  on-disk data formats.
- No new betting features and no ledger behavior changes.
- English-only; logical CSS properties only (Ban 10).
- No new runtime dependencies (dev dependencies unchanged too).
- No visual regression tooling; no density setting; no extra themes/accents.
- Desktop is the app rendered as a centered column, max-width 480px; the
  viewport stays locked (`user-scalable=no`).
- Themes are exactly Light / Dark / OLED; first run follows
  `prefers-color-scheme`; OLED is opt-in; accent defaults to blue; the six
  accents are blue, teal, green, orange, rose, violet.
- Persistence keys are exactly `poker.pot:theme` and `poker.pot:accent`.
- Appearance changes apply and persist instantly; the Settings Save button
  keeps applying only to players/rules.
- The transient screenshot server port is **7407**; it is not registered in the
  dashboard.
- `src/client/styles/tokens.css` is generated by `bun run theme`, committed,
  and never hand-edited.
- The normative reference for colors, Bans, and the accessibility floor is
  `~/.config/opencode/skills/design/references/house-style.md`.
- Verifying commands: `bun run theme`, `bun run test`, `bun run typecheck`,
  `bun run lint`, `bun run build`, `bun run dev`, `bun run screenshots`.
- Commits below happen only while executing this plan, after gate 2 approval;
  no pushes.

```ts

export const ACCENTS = ["blue", "teal", "green", "orange", "rose", "violet"] as const;
```

**Create `scripts/theme.ts`** implementing the formulas in `house-style.md`
exactly, exporting:

```ts
export const ROLES: readonly string[];
export function oklchToHex(l: number, c: number, h: number): string;
export function contrastRatio(hexA: string, hexB: string): number;
export function buildPalette(theme: Theme, accent: Accent): Record<string, string>;
export function generateTokensCss(): string;
```

Requirements:

- Six accent seeds (hue/seed chroma) and all per-role L/chroma factors from the
  house reference; gamut clipping by halving chroma until in sRGB, keeping the
  first in-gamut value; secondary hue unchanged at chroma ×.28; tertiary hue
  +60° at chroma ×.46; neutrals keep documented lightness/chroma with the
  active accent hue; status colors fixed; light/dark container ladders
  interpolate five steps between the documented endpoints; OLED ladder is the
  fixed five values.
- Roles: `primary`, `on-primary`, `primary-container`, `on-primary-container`,
  `surface-tint`, `inverse-primary`, `secondary`, `on-secondary`,
  `secondary-container`, `on-secondary-container`, `tertiary`, `on-tertiary`,
  `tertiary-container`, `on-tertiary-container`, `background`, `on-surface`,
  `on-surface-variant`, `outline`, `surface-1` … `surface-4`, `profit`,
  `loss`, `warning`. `surface-1..4` are ladder steps 2–5 (light/dark) and the
  fixed `#0a0a0b`, `#101012`, `#17171a`, `#1f1f23` for OLED.
- `on-surface-variant` (D32): secondary-text neutral derived from the
  documented neutral lightness with reduced chroma, contrast-verified by T1
  tests (≥ 4.5:1 against background and surfaces). If the derived value fails,
  tune only this role's lightness/chroma until it passes.
- Selector scheme: `:root[data-theme="<theme>"][data-accent="<accent>"]` for
  all 18 combinations, plus a `:root` fallback for light/blue and a
  `@media (prefers-color-scheme: dark)` fallback for `:root:not([data-theme])`.
  Each block sets all color roles and `color-scheme: light|dark`; one shared
  block defines radius, spacing, and type-scale variables.
- Running the file as a script (Bun main module) writes
  `src/client/styles/tokens.css` (header comment: generated by
  `bun run theme`, do not edit).

**Modify `package.json`:** add `"theme": "bun scripts/theme.ts"` to scripts.

**Generate** `src/client/styles/tokens.css` with `bun run theme` and commit it.

### T2 — Theme runtime and pre-paint

**Depends on:** T1 (types/constants).

**Extend `src/client/theme.ts`** (must stay SSR-safe: no top-level `window`/
`document` access):

```ts
export interface Appearance { theme: Theme; accent: Accent }
export function resolveFirstTheme(prefersDark: boolean): Theme;      // dark ? "dark" : "light"
export function readAppearance(storage?: Pick<Storage, "getItem">): Appearance;
export function themeColorFor(theme: Theme): string;                  // #fffbfe | #1c1b1f | #000000
export function applyAppearance(next: Appearance, doc?: Pick<Document, "documentElement" | "querySelector">): void;
export function subscribeAppearance(fn: () => void): () => void;
export function getAppearanceSnapshot(): Appearance;                  // stable ref until change
export function setAppearance(next: Appearance): void;                // validate, persist, apply, notify
export function useAppearance(): [Appearance, (next: Appearance) => void]; // useSyncExternalStore
```

- `readAppearance` validates stored values against `THEMES`/`ACCENTS`, falls
  back to `matchMedia("(prefers-color-scheme: dark)")` when available
  (guarded), then `DEFAULT_THEME`/`DEFAULT_ACCENT`; storage access wrapped in
  try/catch.
- `applyAppearance` sets `data-theme`/`data-accent` on `documentElement`,
  sets `style.colorScheme` to `light`/`dark`, and updates
  `meta[name="theme-color"]` to `themeColorFor(theme)`.

**Modify `index.html`:** inline pre-paint `<script>` before the module script
that reads both keys, resolves first theme via `matchMedia`, and sets the
attributes/color-scheme; static `<meta name="theme-color" content="#fffbfe">`;
`<meta name="color-scheme" content="light dark">`; viewport unchanged otherwise.

**Modify `public/manifest.webmanifest`:** `background_color` and `theme_color`
to `#1c1b1f`.

**Create `tests/theme-runtime.test.ts`:** `resolveFirstTheme` both ways;
`readAppearance` with a fake storage returning valid values, invalid values,
and nothing (falls back to defaults when no `matchMedia`); `themeColorFor` for
all three themes; `applyAppearance` against a minimal fake document object
(dataset/style/querySelector stub) asserting attributes and meta update.

**Verify:** `bun run test`; `bun run typecheck`; `bun run lint`; manual:
`bun run dev`, toggle OS dark mode with cleared storage → first load follows
OS; reload with a stored OLED choice → no light flash.

**Commit:** `feat(theme): add theme runtime and pre-paint script`

## Risks + rollback

- Generator/reference drift — pinned documented primaries and contrast tests
  fail loudly; fix the generator, never the recorded values.
- Contrast failures in a theme — the test identifies the role pair; adjust
  usage (e.g., chips on containers) or the assumed `on-surface-variant`
  values, never the documented house values.
- Flash on load — pre-paint script plus manual reload checks per theme.
- Focus-trap regressions — one shared hook, keyboard pass per screen.
- Layout regressions on small phones — Pixel 7 screenshot set plus a narrow
  viewport spot check during T4/T5.
- Rollback: revert commits; presentation-only, no migrations; leftover
  localStorage keys are inert.
